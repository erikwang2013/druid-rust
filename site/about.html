项目介绍

把 Druid 的能力
带进 Rust 异步世界

保留连接池、SQL 分析与安全防护的核心思路，用 trait 组合和 tokio 重新实现。

它是什么

Druid-Rust 把 Java 生态里久经考验的连接池、SQL 解析、防火墙与监控能力，重写成一套 Rust crate。没有 JVM，没有 DI 容器，也没有 ORM 包装：连接、SQL 与指标都以明确的结构体和 trait 暴露。

项目按职责拆成 10 个 crate，可以只引入 druid-pool 使用连接池，也可以把 druid-wall 与 druid-stat 挂进 Filter 链，一次获得安全与可观测性。

代码遵循 Apache-2.0。项目宠物与视觉资产版权归作者所有，商业使用需取得授权。

四条设计原则

不是把 Java 类层级逐行翻译，而是保留问题本身，重选 Rust 的解法。

异步优先

基于 tokio 的全链路异步 I/O，用 Semaphore 精确限制并发，驱逐与 KeepAlive 由后台任务驱动。

组合优于继承

Java 的类继承体系改为 trait 与 struct 组合，Filter trait 提供完整生命周期钩子，默认空实现。

类型安全

DbType 枚举穷举 30 种数据库方言，SQL 语句与表达式是代数数据类型，编译器检查完整性。

零成本抽象

AOT 编译为原生二进制，PoolGuard 用 RAII 自动归还，无 JIT 预热，也没有运行时容器。

分层与连接生命周期

依赖单向向下，连接从创建到销毁的每一步都有明确归属。

七层，十个 crate

每一层只承担一种职责，下层永远不需要知道上层存在。

层 6druid-console

axum HTTP 监控页面与 JSON 接口，页头按状态切换小德表情。

层 5druid-ha
druid-proxy

加权轮询、健康检查、故障切换，以及 Filter 感知的代理包装层。

层 4druid-pool

连接池核心：并发控制、自动归还、空闲驱逐、KeepAlive 与 PSCache 容器。

层 3druid-wall
druid-stat

AST 级 SQL 防火墙与 SQL 执行统计，通过 Filter 链挂进连接池。

层 2druid-filter

Filter trait、默认空实现、责任链与管理器，负责生命周期事件分发。

层 1druid-sql

词法器、递归下降 Parser、AST、格式化与 Schema 提取。

层 0druid-core
druid-util

错误、配置、30 种方言枚举，以及 SQL 检测、字符串、加密与时间工具。

小德，一只守着连接池的猫头鹰

守夜不眠对应监控统计，德鲁伊兜帽对应安全防护，立于连接池之上对应连接池本身。它的 12 种表情会出现在控制台页头，按当前状态自动切换。
