About

Bringing Druid's capabilities
into async Rust

A Rust port of Alibaba Druid, rebuilt around traits and tokio while keeping the core ideas.

What it is

Druid-Rust rewrites the connection pooling, SQL parsing, firewall and monitoring ideas proven in the Java ecosystem as a set of Rust crates. No JVM, no DI container and no ORM wrapper: connections, SQL and metrics are exposed through explicit structs and traits.

The project is split into ten crates. Use druid-pool on its own for pooling, or put druid-wall and druid-stat into the Filter chain for security and observability.

Code is Apache-2.0. The mascot and visual assets are copyright the author and require a commercial license for commercial use.

Four design principles

Not a line-by-line translation of Java class hierarchy: keep the problem, choose the Rust solution.

Async first

Tokio-based async I/O, Semaphore concurrency control, and background eviction and KeepAlive tasks.

Composition over inheritance

The Java class hierarchy becomes trait and struct composition. The Filter trait exposes lifecycle hooks with no-op defaults.

Type safety

The DbType enum covers 30 database dialects, while SQL statements and expressions are algebraic data types.

Zero-cost abstraction

AOT-compiled native code, PoolGuard RAII return, no JIT warmup and no runtime container.

Layers and connection lifecycle

Dependencies point one way, and every connection state has a clear owner.

Seven layers, ten crates

Each layer has one job. Lower layers never need to know that upper layers exist.

Layer 6druid-console

axum HTTP dashboard and JSON endpoints, with Xiao De changing expression by pool status.

Layer 5druid-ha
druid-proxy

Weighted round-robin, health checks, failover and Filter-aware proxy wrappers.

Layer 4druid-pool

Pool core: concurrency control, automatic return, idle eviction, KeepAlive and PSCache containers.

Layer 3druid-wall
druid-stat

AST-level SQL firewall and SQL execution statistics, attached through the Filter chain.

Layer 2druid-filter

Filter trait, no-op adapter, responsibility chain and manager for lifecycle events.

Layer 1druid-sql

Lexer, recursive-descent parser, AST, formatter and schema visitor.

Layer 0druid-core
druid-util

Errors, configuration and the 30-dialect enum, plus SQL detection, strings, crypto and time helpers.

Xiao De, an owl guarding the pool

Never sleeping maps to monitoring, the druid hood maps to security, and standing on the pool maps to pooling itself. Its 12 expressions appear in the console header and switch with the current state.
