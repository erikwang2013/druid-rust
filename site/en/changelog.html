v1.4.0 2026-10-19AddedFixed

Feature release: pet expression forms enter druid-console, alongside fixes for proxy statement hooks, authenticated favicon loading and clippy on the current stable toolchain. Tests grow from 428 to 431.

Added

  • 12 expression SVGs move into druid-console/assets/pet-expressions/ and ship with the crate. New GET /druid/pet/<name>.svg route.
  • The console header switches expression by state: SQL error to angry, slow SQL to depressed, pool exhausted to knocking, no queries yet to cute, healthy to smile.
  • A drift test keeps docs and crate copies byte-identical. Added a GitHub Social Preview image.

Fixed

  • The proxy layer now dispatches statement_created, statement_error and statement_closed, so failed or blocked statements are counted.
  • With authentication enabled, /druid/mascot.svg and /druid/pet/<name>.svg no longer require a Bearer token, so the favicon does not return 401.
  • WallProvider::new(..., 0) truly disables caching, matching the PSCache zero-means-disabled semantics.
  • Clippy fixes for Rust 1.99 stable, including the move to Atomic::try_update.
v1.3.1 2026-10-01SecurityFixed

A same-day patch after adversarial validation found five more plaintext credential leaks in config Debug output and one packaging defect.

Security: DruidConfig Debug output

  • Parameter values next to userinfo: pick the first @ from the right that is not inside a value, and apply the exemption only to the separator.
  • Scheme segment: compare against the SAFE_SCHEME_LABELS allowlist; unknown labels are redacted entirely.
  • Key labels: values still use substring matching in the fail-closed direction, but key names can only echo from an exact allowlist.
  • One rule: every segment is judged, and the judging scope equals the applied scope.

Packaging and release

  • Mascot assets move into the crate, fixing cargo package failures, with a drift test.
  • druid-wall and druid-console are published to crates.io for the first time.
  • All ten crates get readme metadata so crates.io shows the project README.
v1.3.0 2026-10-01BreakingSecurity

A deep review and three rounds of adversarial validation. The core finding: in 1.2.0 the SQL firewall and statistics never ran on the pool path, because filters had nowhere to attach and PoolGuard exposed only the raw connection.

Breaking changes

  • The firewall is fail-closed by default: unparsable or unrecognized statements are rejected. Escape hatch: deny_unparsable = false.
  • DruidConfig::filters is not wired; a non-empty value makes init() fail. Use DruidDataSource::with_filters(...).
  • DruidError is #[non_exhaustive]; downstream exhaustive matches need a _ => arm.
  • max_lifetime_ms is now judged by physical creation time. The old last-used time made it ineffective for hot connections.
  • Invalid configs such as initial_size > max_active fail at init through DruidConfig::validate().
  • druid-ha removes the unused NodeStatus::Testing. substitute_params is deprecated in favor of substitute_params_mysql.

Added

  • Construction-time injection: with_filters() and with_chain(), configured before the chain is wrapped in Arc.
  • PoolGuard::execute() and query(): the only path where SQL reaches the Filter chain. connection() remains the escape hatch.
  • Five lifecycle hooks that were defined but never dispatched are wired, plus impl Filter for Arc<T>.
  • Console token authentication, constant-time comparison, Cache-Control: no-store and pagination.
  • Wall deny_unparsable, a transaction-control safe channel, and broader DenyOperation classification.
  • Parser support for LIMIT offset, count, @var and EXPLAIN.
  • HA failure/success thresholds, probe timeouts and a stoppable health-check loop.

Security fixes

  • The firewall logged and allowed on parse failure, and quick_check discard denial results. Eight bypasses closed.
  • The function denylist did not recurse into arguments, so COALESCE(SLEEP(5),0) slipped through. It now recurses.
  • CREATE TABLE ... DEFAULT (RAND()) bypass reproduced on real databases and closed.
  • deny_keywords was blinded by quoting twice. Matching text is rebuilt from the lexer token stream.
  • substitute_params backslash injection. Added a MySQL-safe variant.
  • Plaintext credentials in config Debug output. Redaction now works segment by segment.
  • The console exposed raw SQL without authentication. Added a token and loopback guidance.
  • Crypto did not enable the zeroize features, so key material was not cleared on drop.

Correctness and concurrency

  • Cancellation safety: a pending guard is created early, so cancellation does not leak a physical connection.
  • Fixed connections being created after close, distorted return-validation counts, and close not waking waiters.
  • KeepAlive no longer closes connections in use, and shares state semantics with the borrow path.
  • Fixed permits released before the connection returned, which could exceed max_active.
  • DruidDataSource now has Drop, so background tasks and idle connections do not leak.
  • HA fixes for stuck nodes, no per-probe timeout, one-failure death, and an unstoppable loop.
  • Statistics fixes for unbounded SQL tables, drifting active/idle counts and printing under lock.
  • Parser fixes for NOT precedence, recursive depth, silent truncation and treating every -- as a comment.
  • Formatter fixes for string escaping, lost CREATE TABLE constraints, missing parentheses and literal JOIN output.

v1.1.8 2026-08-02AddedFixed
  • CTE/WITH support in the parser, AST, formatter and visitor.

  • Cache-hit, waiting, create and destroy counters are complete.

  • axum console, Filter chain architecture and AES-256-GCM helpers.
  • 61 unit and integration tests.
