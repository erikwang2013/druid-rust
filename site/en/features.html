Feature evolution

Capabilities are built one version at a time

From the first ten crates to a wired Filter chain, then Xiao De's expressions in the console. Every step belongs to a release.

Six capabilities today

The pool is the core. The Filter chain extends it with security and observability. Every crate is usable on its own.

druid-pool

Async connection pool

Semaphore concurrency control, PoolGuard return on drop, and background eviction and KeepAlive.

  • warm-up
  • borrow timeout
  • validation
  • KeepAlive
  • PSCache

druid-sql

SQL parser

From the lexer to a recursive-descent parser, AST and schema extraction, feeding the firewall and formatter.

  • 80+ tokens
  • 22 expressions
  • 30 dialects
  • SchemaVisitor

druid-wall

SQL firewall

AST-level checks for dangerous operations, functions and statement shapes. Fail-closed by default.

  • required WHERE
  • multi-statement
  • file writes
  • 512-entry cache

druid-stat

Monitoring

Per-SQL count, latency, max latency and errors, with slow SQL alerts and lock-free metrics.

  • slow SQL
  • PoolMetrics
  • StatFilter
  • Prometheus ready

druid-ha

High availability and proxy

Weighted round-robin sources, async health checks, and threshold-based failover to avoid flapping.

  • failover
  • health checks
  • mark_down
  • ProxyStatement

druid-console

Web console

An axum dashboard and JSON endpoints with Bearer token support and Xiao De expressions by status.

  • /druid/stat.json
  • /druid/sql.json
  • slow SQL API
  • 12 expressions

Version evolution

What each release changed. The full itemized history lives in the changelog.

v1.1.0 2026-07-31

Ten pieces in place

First release with ten crates: async pool, SQL parser, firewall, statistics, HA and console. 61 tests.

v1.1.8 2026-08-02

Parser and lifecycle hardening

CTE/WITH support, a KeepAlive TOCTOU fix, more accurate create, destroy and waiting metrics, and broader firewall clause coverage.

v1.1.9 2026-08-02

Engineering baseline

CI, LICENSE, CHANGELOG and CONTRIBUTING, plus crate metadata and a dependency cleanup.

v1.2.0 2026-09-26

Xiao De arrives

The mascot enters the README and console, with architecture, feature and lifecycle diagrams. Tests grow from 61 to 231.

v1.3.0 2026-10-01

Wire the Filter chain

A deep review found that the SQL firewall and statistics never ran on the pool path. This release adds construction-time filters and PoolGuard execute/query, makes the firewall fail-closed, and fixes 11 security and concurrency defects.

v1.3.1 2026-10-01

Boundaries

Three more config Debug redaction edges, mascot assets moved into the crate for packaging, and the first crates.io release for druid-wall and druid-console.

v1.4.0 2026-10-19

Expressions and details

12 pet expressions in the console, proxy statement lifecycle hooks, authenticated favicon loading, and 431 tests.

Known boundaries

Some limits are deliberate security trade-offs, documented in code and docs.

Firewall direction: UNION, SHOW, USE and SET remain denied. USE tears down schema restrictions and SET changes the parsing semantics of later statements, which a stateless text firewall cannot safely allow.
Prefer false positives: quoted identifiers contribute their inner text to matching, which can over-report under the default sql_mode. The direction is to block suspicious input, not to let it through.
Validation timeout: test_on_return has no timeout when validation_query_timeout_secs = 0 (the default). A network black hole can hold a concurrency permit for a long time.
Parser: table-level PRIMARY KEY (id) and EXPLAIN FORMAT=JSON|TREE are not parsed yet.
