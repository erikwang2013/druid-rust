The pool is the core. Everything else grows around it.

Ten crates across seven layers. Dependencies point one way: upper layers may use lower layers, never the reverse.

druid-pool

Semaphore-based concurrency control, PoolGuard RAII return, idle eviction and KeepAlive.

druid-wall

AST-level SQL firewall. Unparsable or unrecognized statements are rejected by default.

druid-stat

Per-SQL counts, latency, errors and slow queries, with lock-free metrics ready for Prometheus.

Six capabilities, one dependency graph

From connection lifecycle to SQL semantics. Use any crate alone, or compose them through the Filter chain.

01

Async connection pool

Tokio-based async I/O with warm-up, borrow timeouts, validation, idle eviction and KeepAlive.

druid-pool
02

SQL parser

80+ token lexer, recursive-descent parser, 22 expression types and 30 database dialects.

druid-sql
03

SQL firewall

Operation denylist, dangerous functions, required WHERE, file writes and multi-statement checks. Fail-closed by default.

druid-wall
04

Monitoring

Per-SQL counts, latency, errors and slow queries, with lock-free pool metrics.

druid-stat
05

HA and proxy

Weighted round-robin sources, async health checks, automatic failover and statement interception.

druid-ha
06

Web console

An axum dashboard and JSON endpoints, with Xiao De changing expression based on pool state.

druid-console

Three-minute setup

Add the crates to Cargo.toml, implement Driver and Connection, and bring your own database driver.

Full installation guide →
Note: SQL must go through guard.execute() or guard.query() for filters to run.
Cargo.toml 
# Pick what you need, version 1.4
[dependencies]
druid-core = "1.4"
druid-pool = "1.4"
druid-wall = "1.4"
druid-stat = "1.4"
tokio = { version = "1", features = ["full"] }
