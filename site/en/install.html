Install

Put the pool into your project

Druid-Rust is a Rust workspace. Use the core crate alone, or combine pooling, firewall, statistics and the console.

Contents

Current version: 1.4.0 · 431 tests passing · Apache-2.0. Dependency examples use version 1.4.

Requirements

  • Rust stable, edition 2021.
  • The tokio async runtime. Examples use features = ["full"].
  • A database and a driver adapter implementing the Driver and Connection traits. The project does not bundle a database driver.

If you only need the SQL parser or firewall, add that crate alone and skip the pool.

Dependencies

Add the crates you need to Cargo.toml. The minimal combination is druid-core plus druid-pool.

Cargo.toml 
# Version 1.4
[dependencies]
druid-core = "1.4"
druid-pool = "1.4"
druid-wall = "1.4"
druid-stat = "1.4"
tokio = { version = "1", features = ["full"] }

Or use cargo add:

Terminal 
cargo add druid-core druid-pool druid-wall druid-stat
cargo add tokio --features full

Minimal example

Create a data source, warm up connections, borrow a guard and let drop return it. Replace your_driver with your driver implementation.

src/main.rs 
use druid_core::DruidConfig;
use druid_pool::DruidDataSource;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut config = DruidConfig::new(
        "mysql://localhost:3306/mydb",
        "root",
        "password",
    );
    config.initial_size = 5;
    config.max_active = 20;
    config.min_idle = 3;

    // your_driver must implement druid_pool::Driver
    let ds = DruidDataSource::new(your_driver, config);
    ds.init().await?;

    let guard = ds.get_connection().await?;
    // Use guard.execute() / guard.query() so filters run
    drop(guard); // returned automatically

    ds.close().await?;
    Ok(())
}
Note: guard.connection() is the escape hatch that bypasses filters. SQL through it skips both the firewall and statistics.

Build from source

Build the whole workspace when developing or when you need unreleased changes.

Terminal 
git clone https://github.com/erikwang2013/druid-rust.git
cd druid-rust
cargo build --release
cargo test --workspace
cargo run --example basic

Release builds enable LTO, codegen-units = 1 and opt-level = 3.

Verify

Run a quick compile check, then confirm the target crate is in the dependency tree.

Terminal 
cargo check
cargo tree -p druid-pool

The full workspace test run should report 431 passing tests.

FAQ

Why does init fail when I set filters?

DruidConfig::filters is not wired. Use DruidDataSource::with_filters(driver, config, filters) to attach the chain at construction time.

Why is valid SQL rejected by the firewall?

The firewall is fail-closed, so syntax the parser does not yet support is rejected, including UNION, SHOW, USE, SET and EXPLAIN FORMAT=TREE. Set deny_unparsable = false only after reviewing the risk.

Why does the console return 401?

With start_server_with_token(), data and page endpoints require Authorization: Bearer <token>. Static pet assets stay public so the browser can load the favicon.

Can I use sqlx or tokio-postgres directly?

The project defines its own async Driver and Connection traits and does not bundle an ORM. Write a small adapter from your database client to those traits.
