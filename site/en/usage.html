Create a data source

DruidConfig holds the connection details and pool parameters. Set warm-up, minimum idle and maximum active, then call init() to build the initial connections.

Rust 
use druid_core::DruidConfig;
use druid_pool::DruidDataSource;

let mut config = DruidConfig::new(
    "mysql://localhost:3306/mydb",
    "root",
    "password",
);
config.initial_size = 5;
config.min_idle = 3;
config.max_active = 20;
config.max_wait_ms = 3_000;

let ds = DruidDataSource::new(your_driver, config);
ds.init().await?;

Run SQL

A borrowed PoolGuard returns automatically on drop, even during a panic. Use execute() or query() so the Filter chain runs.

Rust 
let guard = ds.get_connection().await?;

let affected = guard.execute(
    "UPDATE users SET active = 1 WHERE id = 42",
).await?;

drop(guard); // returned automatically
Escape hatch: guard.connection().execute() bypasses filters. It is useful for explicit operational scripts, but the firewall and statistics will not run.

SQL firewall

Filters are injected at construction time. The chain is configured before it is wrapped in Arc, so there is no registration race.

Rust 
use druid_pool::DruidDataSource;
use druid_wall::{WallConfig, WallFilter};

let ds = DruidDataSource::with_filters(
    your_driver,
    config,
    vec![Box::new(WallFilter::new(WallConfig {
        update_delete_require_where: true,
        deny_functions: vec!["SLEEP".into(), "BENCHMARK".into()],
        ..Default::default()
    }))],
);
ds.init().await?;

// SQL must go through guard.execute() / query() for filters to run
let affected = guard.execute(
    "DELETE FROM t WHERE id = 1",
).await?;
Fail-closed: unparsable or unrecognized statements are rejected by default. If your application uses syntax the parser does not support yet, it will look like valid SQL being rejected. Disable deny_unparsable only after reviewing the risk.

SQL monitoring

Pass an Arc<StatFilter> into the chain and keep the handle for reads. Bind the pool metrics so the console reads authoritative active and idle counts.

Rust 
use druid_pool::DruidDataSource;
use druid_stat::StatFilter;
use std::sync::Arc;

let stat = Arc::new(StatFilter::new("mydb", 1000)); // 1000ms slow SQL threshold

let ds = DruidDataSource::with_filters(
    your_driver,
    config,
    vec![Box::new(stat.clone())],
);
ds.init().await?;

stat.bind_metrics(ds.metrics_arc());

let sql_stats = stat.get_sql_stats();     // sorted by latency
let slow_sql = stat.get_slow_sql();        // above the threshold
let ds_stat = stat.get_datasource_stat();  // pool overview
println!("executions: {}, slow SQL: {}", ds_stat.execute_count, slow_sql.len());

The SQL statistics table holds 1000 entries by default and evicts the coldest by total latency. Use StatFilter::with_max_sql_size(n) for dynamic SQL workloads.

Web console

The console exposes raw SQL, so set a token in production or bind it to loopback only.

Rust 
use druid_console;
use std::sync::Arc;

let stat = Arc::new(StatFilter::new("app-db", 500));
tokio::spawn(async {
    druid_console::start_server_with_token(
        stat,
        "127.0.0.1:9090",
        Some("my-secret".into()),
    )
    .await
    .unwrap();
});

// Open http://127.0.0.1:9090/druid/index.html
// Requests need Authorization: Bearer my-secret

The static pet assets /druid/mascot.svg and /druid/pet/<name>.svg do not require auth because they contain no SQL or statistics.

High availability

Weighted round-robin across data sources. Failover only happens after a failure or success threshold is reached, which avoids flapping.

Rust 
use druid_ha::HighAvailableDataSource;
use std::time::Duration;

let mut ha = HighAvailableDataSource::new();
ha.add_node("master", master_ds, 2);   // weight 2
ha.add_node("slave-1", slave1_ds, 1);
ha.add_node("slave-2", slave2_ds, 1);
ha.set_check_interval(Duration::from_secs(30));

let ds = ha.get_datasource().await?;
ha.mark_down("master");  // manual failover
ha.mark_up("master");    // recover

let ha = std::sync::Arc::new(ha);
let _handle = ha.spawn_health_check_loop();

Custom filters

Implement the Filter trait hooks you need. There is no base class to inherit.

Rust 
use druid_filter::{Filter, FilterContext};
use druid_core::DruidError;

struct MyLogFilter;

impl Filter for MyLogFilter {
    fn name(&self) -> &'static str { "my-log" }

    fn connection_borrowed(&self, ctx: &FilterContext, wait_ms: u64) {
        tracing::info!("conn borrowed: wait={}ms", wait_ms);
    }

    fn statement_execute_before(&self, ctx: &FilterContext) -> Result<(), DruidError> {
        if let Some(sql) = &ctx.sql {
            tracing::debug!("executing: {}", sql);
        }
        Ok(())
    }

    fn statement_execute_after(&self, ctx: &FilterContext, elapsed_ms: u64, rows: u64) {
        tracing::info!("executed in {}ms, {} rows", elapsed_ms, rows);
    }
}

Security notes

  • Do not expose the console without authentication in production. Raw SQL may contain literals and sensitive values.
  • Send application SQL through guard.execute() and guard.query(); otherwise the firewall and statistics are bypassed.
  • The firewall is fail-closed by default. Review the parser gaps before disabling deny_unparsable.
  • DruidConfig Debug output redacts credentials segment by segment, but do not print whole config objects to production logs.
  • The crypto helpers do not implement a KDF. Do not use a password directly as a key.
