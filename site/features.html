功能迭代

能力不是一次写完的

从最初的十块拼图，到 Filter 真正接入连接池，再到小德的表情进入控制台。每一步都对应一次版本。

现在的六块能力

以连接池为核心，通过 Filter 责任链向外扩展。每块能力都可以单独引入。

druid-pool

异步连接池

Semaphore 精确控制并发，PoolGuard 在 drop 时自动归还，后台任务负责驱逐与保活。

  • 预热
  • 获取超时
  • 借还验证
  • KeepAlive
  • PSCache 容器

druid-sql

SQL 解析引擎

从词法器到递归下降 Parser，再到 AST 与 Schema 提取，为防火墙和格式化提供结构化输入。

  • 80+ Token
  • 22 种表达式
  • 30 种方言
  • SchemaVisitor

druid-wall

SQL 防火墙

基于 AST 检查危险操作、函数与语句结构。解析失败或类型无法识别时默认拒绝。

  • 强制 WHERE
  • 多语句拦截
  • 文件写入拦截
  • 512 条缓存

druid-stat

监控统计

记录每条 SQL 的次数、耗时、最大耗时与错误，慢 SQL 自动告警，指标无锁累加。

  • 慢 SQL
  • PoolMetrics
  • StatFilter
  • Prometheus 对接

druid-ha

高可用与代理

加权轮询多数据源，异步健康检查，连续失败或成功达到阈值才切换，避免抖动。

  • 故障切换
  • 健康检查
  • mark_down
  • ProxyStatement

druid-console

Web 控制台

axum 驱动的监控页面与 JSON 接口，支持 Bearer token，页头根据状态切换小德表情。

  • /druid/stat.json
  • /druid/sql.json
  • 慢 SQL 接口
  • 12 种表情

版本演进

这里只讲每个版本改变了什么。逐条修复记录在版本日志里。

v1.1.0 2026-07-31

十块拼图就位

首次发布 10 个 crate：异步连接池、SQL 解析器、防火墙、统计、高可用与控制台。61 项测试起步。

v1.1.8 2026-08-02

解析器与生命周期补强

加入 CTE/WITH 支持，修复 KeepAlive 的 TOCTOU 问题，补齐驱逐、创建与销毁路径的指标，防火墙覆盖更多 SQL 子句。

v1.1.9 2026-08-02

工程化补齐

补上 CI、LICENSE、CHANGELOG 与 CONTRIBUTING，10 个子 crate 补齐元数据，清理未使用的依赖。

v1.2.0 2026-09-26

小德登场

项目宠物「小德」进入 README 与控制台，架构图、功能图、生命周期图一并补齐，测试数从 61 增长到 231。

v1.3.0 2026-10-01

把 Filter 真正接上

深度审查发现 SQL 防火墙与统计在连接池路径上从未执行。本版引入构造期注入与 PoolGuard 的 execute/query 入口，防火墙改为默认 fail-closed，并修复 11 项安全与并发缺陷。

v1.3.1 2026-10-01

边界收敛

修掉三处配置 Debug 的口令脱敏边界，把吉祥物资产移入 crate 内部解决打包失败；druid-wall 与 druid-console 首次发布到 crates.io。

v1.4.0 2026-10-19

表情与细节

12 种宠物表情进入控制台并按状态切换，代理层补齐语句生命周期钩子，鉴权下 favicon 不再 401，测试数达到 431。

已知边界

有些限制是刻意的安全取舍，已经在代码与文档中标注。

防火墙方向：UNION、SHOW、USE、SET 维持拒绝。USE 会拆掉 schema 限制，SET 会改变后续语句的解析语义，无状态文本防火墙无法安全放行。
宁可误报：引号标识符会取引号内原文参与匹配，默认 sql_mode 下可能多报。方向是拦住可疑输入，而不是放过。
验证超时：test_on_return 在默认 validation_query_timeout_secs = 0 时没有超时，网络黑洞会长期占用一个并发许可。
解析器：表级约束 PRIMARY KEY (id) 与 EXPLAIN FORMAT=JSON|TREE 尚不可解析。
