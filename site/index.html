连接池是核心，其余能力围绕它生长

10 个 crate 分成 7 层，依赖单向向下。上层可以依赖下层，下层永不反向依赖上层。

druid-pool

Semaphore 精确并发控制、PoolGuard RAII 自动归还、空闲驱逐与 KeepAlive 保活。

druid-wall

AST 级 SQL 防火墙，解析失败默认拒绝，拦住注入、危险操作与无 WHERE 的更新。

druid-stat

每条 SQL 的次数、耗时、错误与慢查询都在视野内，lock-free 指标可对接 Prometheus。

六块能力，一个依赖图

从连接生命周期到 SQL 语义分析，每一块都能独立使用，也能通过 Filter 责任链组合。

01

异步连接池

基于 tokio 的全链路异步 I/O，支持预热、获取超时、借还验证、空闲驱逐与 KeepAlive。

druid-pool
02

SQL 解析器

80+ Token 词法分析、递归下降 Parser、22 种表达式与 30 种数据库方言适配。

druid-sql
03

SQL 防火墙

操作黑名单、危险函数、强制 WHERE、文件写入与多语句检查，默认 fail-closed。

druid-wall
04

监控统计

SQL 执行画像、慢 SQL 告警、连接池实时指标，全部通过 AtomicU64 无锁累加。

druid-stat
05

高可用与代理

加权轮询多数据源、异步健康检查、自动故障切换，代理层拦截连接与语句。

druid-ha
06

Web 控制台

axum 驱动的监控页面与 JSON 接口，页头会根据状态切换小德的表情。

druid-console

三分钟接入

把依赖加进 Cargo.toml，实现 Driver 与 Connection trait，驱动由你选择。

完整安装文档 →
提示：SQL 需要走 guard.execute() 或 guard.query()，防火墙与统计才会被调用。
Cargo.toml 
# 按需引入，版本统一为 1.4
[dependencies]
druid-core = "1.4"
druid-pool = "1.4"
druid-wall = "1.4"
druid-stat = "1.4"
tokio = { version = "1", features = ["full"] }
