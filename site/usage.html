使用说明

连接池、防火墙与监控
按场景接入

所有示例假设 config 已由 DruidConfig 创建，your_driver 是实现了 Driver 的适配层。

目录

创建数据源 执行 SQL SQL 防火墙 SQL 监控 Web 控制台 高可用 自定义 Filter 配置参考 安全提示

创建数据源

DruidConfig 保存连接信息与池参数。设置预热、最小空闲与最大活跃数后，调用 init() 建立初始连接。

Rust 
use druid_core::DruidConfig;
use druid_pool::DruidDataSource;

let mut config = DruidConfig::new(
    "mysql://localhost:3306/mydb",
    "root",
    "password",
);
config.initial_size = 5;
config.min_idle = 3;
config.max_active = 20;
config.max_wait_ms = 3_000;

let ds = DruidDataSource::new(your_driver, config);
ds.init().await?;

执行 SQL

借出的 PoolGuard 在 drop 时自动归还，panic 也不会泄漏连接。SQL 走 execute() 或 query()，Filter 链才会被调用。

Rust 
let guard = ds.get_connection().await?;

let affected = guard.execute(
    "UPDATE users SET active = 1 WHERE id = 42",
).await?;

drop(guard); // 自动归还，无需显式释放
逃生通道：guard.connection().execute() 会绕过 Filter。它适合运维脚本等明确场景，但防火墙与统计都不会生效。

SQL 防火墙

Filter 在构造期注入。链在包装为 Arc 前完成配置，运行期只读，不存在注册竞态。

Rust 
use druid_pool::DruidDataSource;
use druid_wall::{WallConfig, WallFilter};

let ds = DruidDataSource::with_filters(
    your_driver,
    config,
    vec![Box::new(WallFilter::new(WallConfig {
        update_delete_require_where: true,
        deny_functions: vec!["SLEEP".into(), "BENCHMARK".into()],
        ..Default::default()
    }))],
);
ds.init().await?;

// SQL 必须走 guard.execute() / query()，Filter 才会被调用
let affected = guard.execute(
    "DELETE FROM t WHERE id = 1",
).await?;
fail-closed：解析失败或语句类型无法识别时默认拒绝。若业务用到解析器尚未支持的语法，会表现为合法 SQL 被拒。确认风险后再关闭 deny_unparsable。

SQL 监控

把 Arc<StatFilter> 传进 Filter 链，同时保留句柄供链外读取。绑定池内权威指标后，控制台的 active/idle 直接读池计数。

Rust 
use druid_pool::DruidDataSource;
use druid_stat::StatFilter;
use std::sync::Arc;

let stat = Arc::new(StatFilter::new("mydb", 1000)); // 1000ms 慢 SQL 阈值

let ds = DruidDataSource::with_filters(
    your_driver,
    config,
    vec![Box::new(stat.clone())],
);
ds.init().await?;

stat.bind_metrics(ds.metrics_arc());

let sql_stats = stat.get_sql_stats();     // 按耗时排序
let slow_sql = stat.get_slow_sql();        // 超过阈值
let ds_stat = stat.get_datasource_stat();  // 连接池概览
println!("执行次数: {}, 慢SQL: {}", ds_stat.execute_count, slow_sql.len());

SQL 统计表默认上限 1000 条，按总耗时淘汰最冷条目。动态 SQL 较多时可用 StatFilter::with_max_sql_size(n) 调整。

Web 控制台

控制台会暴露 SQL 原文，生产环境必须设置 token，或者只绑定回环地址。

Rust 
use druid_console;
use std::sync::Arc;

let stat = Arc::new(StatFilter::new("app-db", 500));
tokio::spawn(async {
    druid_console::start_server_with_token(
        stat,
        "127.0.0.1:9090",
        Some("my-secret".into()),
    )
    .await
    .unwrap();
});

// 浏览器访问 http://127.0.0.1:9090/druid/index.html
// 请求需带 Authorization: Bearer my-secret

静态宠物资源 /druid/mascot.svg 与 /druid/pet/<name>.svg 不要求鉴权，因为它们不包含 SQL 或统计数据。

高可用

加权轮询多个数据源，健康检查连续失败或成功达到阈值才切换，避免抖动。

Rust 
use druid_ha::HighAvailableDataSource;
use std::time::Duration;

let mut ha = HighAvailableDataSource::new();
ha.add_node("master", master_ds, 2);   // 权重 2
ha.add_node("slave-1", slave1_ds, 1);
ha.add_node("slave-2", slave2_ds, 1);
ha.set_check_interval(Duration::from_secs(30));

let ds = ha.get_datasource().await?;
ha.mark_down("master");  // 手动故障切换
ha.mark_up("master");    // 恢复

let ha = std::sync::Arc::new(ha);
let _handle = ha.spawn_health_check_loop();

自定义 Filter

实现 Filter trait 的钩子即可插入自己的逻辑，不需要继承任何基类。

Rust 
use druid_filter::{Filter, FilterContext};
use druid_core::DruidError;

struct MyLogFilter;

impl Filter for MyLogFilter {
    fn name(&self) -> &'static str { "my-log" }

    fn connection_borrowed(&self, ctx: &FilterContext, wait_ms: u64) {
        tracing::info!("conn borrowed: wait={}ms", wait_ms);
    }

    fn statement_execute_before(&self, ctx: &FilterContext) -> Result<(), DruidError> {
        if let Some(sql) = &ctx.sql {
            tracing::debug!("executing: {}", sql);
        }
        Ok(())
    }

    fn statement_execute_after(&self, ctx: &FilterContext, elapsed_ms: u64, rows: u64) {
        tracing::info!("executed in {}ms, {} rows", elapsed_ms, rows);
    }
}

安全提示

  • 生产环境不要无鉴权暴露控制台，SQL 原文可能包含字面量与敏感值。
  • 业务 SQL 统一走 guard.execute() 与 guard.query()，否则防火墙与统计都会被绕过。
  • 防火墙默认 fail-closed。关闭 deny_unparsable 前，先确认解析器缺口带来的风险。
  • DruidConfig 的 Debug 输出做了逐段口令脱敏，但仍不建议把配置对象整体打印到生产日志。
  • 密码工具模块尚未实现 KDF，口令不能直接当作密钥使用。
